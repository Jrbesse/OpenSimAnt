# Dev Log #2 — v1.0.0, and the Difference Between Built and Proven

*November 11, 2026*

**OpenSimAnt v1.0.0 is out.** Three packages, no original data in any of them, and a clean asset pack
that the game builds, plays and screenshots itself before the archives are packed. This is a private,
personal build — the public release is the one after the rename pass — so this entry is about what
changed between **v0.2.1** (7 November) and now, and about the thing that occupied nearly all of it:
making every claim in the repo checkable by a machine instead of by me.

Thirteen pull requests and ten closed issues between v0.2.1's publication and v1.0.0's — eleven with the
tag issue, which closed minutes after the release. Almost none of them added a feature.

## Measuring a copy without comparing pixels

The gate before the pack could ship publicly was issue **#20**: judge the clean pack against the
original for anything too close. That sounds like an afternoon of eyeballing and is actually a
measurement problem, because the two packs are not in the same colour space — the clean pack is
Mac-palette, the original is EGA. Comparing RGB values would report a difference everywhere and prove
nothing.

So `tools/review/similarity.py` compares **palette indices**, and adds three measures that survive a
palette swap: silhouette IoU (does the shape match, regardless of colour), colour-role Jaccard (does
the *role* of each colour match — eye, body, highlight), and per-font glyph identity. Sound is judged
by duration plus envelope correlation; music by note triples.

What came back:

| Area | The number | Verdict |
|---|---|---|
| 252 bitmaps | silhouette IoU median **1.000**; 29 of 36 captures **0 of 307,200 px** | pass |
| 34 window layouts | byte-identical through the encoder; the windows sit where and at the size the original puts them, and the capture residues are #18, #25, #29, #54, #55 | pass |
| Text | 107 lists / 518 entries: 70 identical, all labels or UI fragments but one | one line to rewrite |
| Fonts | identical glyph share 4.3 / 4.0 / 2.7 / **13.6 %** for fonts 0–3 | one face to look at |
| Sound | 35/35 durations equal; envelope correlation median 0.210 | structurally pass; needs ears |
| Music | **0 identical note triples in 30 songs**; note counts 0.905–1.893× | structurally pass |

Five findings came out of it, and the interesting one is a rule question rather than a defect: six
clean bitmaps are **identical to the original and correct** — two lattice strips, a solid rectangle,
two one-pixel sprites, a raindrop. A clean-room rule written as "no asset may be identical" would
condemn them. #53 asks for the class they belong to: assets whose form the measurement fixes.

## A gate that passed over nothing

The replay suite is the oracle the merge job trusts: it replays 26 trace files, 229,778 calls and
74,500 `SimStep` records, and compares the C# port against the reference. On a fresh clone it printed
`ALL OK` and exited **0** — with an empty `build/traces/` directory. A green gate over zero verified
code is worse than a red one, because it is indistinguishable from success.

The fix is a `ReplayRunner` that names every path which yielded no trace and exits 1, with
`--allow-empty` as the one deliberate exception (it prints that the run proves nothing). Five tests
assert the **return code**, not the printed line — including "an explicit path that matches nothing
exits non-zero and names the path". A run that replayed 26 traces still exits 0, and that case is a
test too.

The same class of bug was in the sprite pipeline: `build.yml` never regenerated the sheets, so a
`.pix` that disagreed with its templates passed CI. It now regenerates and fails on any diff — and it
was verified to have teeth by committing a hand-edited pixel: the generator still said *all checks
passed* (it checks its templates, not the file) while the diff step exited 1 and showed the row.

## Why CI and releases run on different machines

Build and test moved to a self-hosted runner (the Proxmox container on the same box as the nightly
work) because hosted minutes on a private repo are billed and self-hosted ones are not. Releases did
**not** move with them: that container has an unresolved intermittent write-corruption fault, and the
distinction matters — a bad write in CI is a red build, a bad write in a published download is a
broken game that people have already paid no money for but will still be annoyed by.

The rollback is one variable: delete `CI_RUNNER` and the jobs go back to `ubuntu-latest` with no code
change.

## The licences, down to the byte

`LICENSE` is MIT and covers the code — **415 tracked files** at the v1.0.0 tag. `LICENSE-ASSETS` is
CC BY 4.0 for the clean pack — **440 files**: art, layouts, fonts, text, sound, music. No path is
under both.

The file opens with the attribution line a reuser has to ship, then the unabridged licence text, and
lines 30–425 are byte-identical to `creativecommons.org/licenses/by/4.0/legalcode.txt` — verified by
`diff`, `sha256 9ba9550a…`, 18,657 bytes. Both files ship **inside every archive**, because the
attribution requirement fails if a downloader never sees the repository.

The README gained a known-differences section that names the two accepted capture diffs with their
pixel counts, coordinates and colours — `yard`, 9 px in two columns at x=264 and x=288, y=195–199,
where the original draws violet `(242,8,133)` and background green `(28,182,20)` and the remake draws
background grey `(64,64,64)` and a brown sprite pixel; `yardfront`, 2 px at y=83. Where a reading is a
hypothesis rather than a measurement, the section says so, which is the only way a "known difference"
list stays worth reading.

## One interpreter, written down

`make_sprites.py` is what the clean art is built from, and its README said `python make_sprites.py`,
which dies at `import numpy` on this box — one nightly session worked around it with a throwaway venv,
and the next session and the reviewer hit the same wall. The makers use numpy in 28 places and Pillow
in 15; `tools/clean_pack/build.py` needs neither, which is why the pack builder worked all along.

Now there is a `requirements.txt` beside the makers, the recreate commands, and READMEs that name the
interpreter. Rebuilding in place produced **no diff** in the four `.pix` files or the preview — the
sheets really are the script's output, under numpy 2.5.4 and Pillow 13.0.0 rather than whatever CI
happens to pull.

## How a release gets built

The notes every release is published with now come from `docs/RELEASE_NOTES_TEMPLATE.md`, copied into
the workflow rather than typed into it, and set on both the create and the update path. That is
deliberate: the licence line and the disclaimer cannot be dropped from a release by forgetting them.

The export job builds the clean pack from source, **plays the game on it under a virtual screen and
saves frames** (a crash or a missing resource fails the run), then cross-exports Windows, macOS and
Linux from one Linux runner and ad-hoc signs the macOS app. Every package carries
`HOW_TO_PLAY.txt`, `THIRD_PARTY_NOTICES.txt`, `LICENSE` and `LICENSE-ASSETS`.

One thing worth fixing while we were here: v1.0.0 is a **normal** release because it was created on the
web page, not because the workflow said so. A tag pushed without a release took the `gh release create`
path, which titled it `(test build)` and marked it `--prerelease` — an assumption that every tag was a
test build, true until it wasn't. PR **#59** removes it, and it merged the same afternoon; from here, a
tag is a release.

## What's next

- **The listening pass (#21)** — 30 songs and 35 effects heard end to end. It needs the A/B stitching
  tool (#35) first: both packs rendered through one mixer, in identical track order.
- **The public decision (#22)** and the **rename pass (#36)** — v1.0.0 is private by choice; "finished"
  and "published" are separate decisions.
- **Font 3 (#52)** — 30 of 221 glyphs pixel-identical, digits and capitals included. The likeliest
  candidate for anything too close in the pack.
- **The file dialog capture (#54)** — 989 px, and the one capture that cannot be compared yet. The
  comparison renders the dialog against whatever directory is on the machine, so the diff is the file
  listing and not the renderer; it is a render difference only once the recording and the render see
  the same files.
- **The 50 % stipple phase (#55)** — the one reproducible render difference still open: `editfront` and
  `popup` differ by 32 px in the same 8×8 block at (432,102), 16 px light grey where the original has
  black and 16 black where it has light grey, a stipple drawn in the other phase. Understood, not fixed.
- And the diffs we accept rather than schedule — `yard`, 9 px (#25) and `yardfront`, 2 px (#29) — are
  recorded with their coordinates and colours in README §Known differences, so they are neither fixed
  nor silent; `gameover`'s 144 px of map art left of the box (the box itself identical) is recorded in
  #18's closing comment, and is a candidate for that section once it is worth listing three.

The simulation was already done and already matched. What v1.0.0 adds is the part that lets other
people have it, with a machine able to check every sentence of this entry.
