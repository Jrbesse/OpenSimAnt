# Dev Log #3 — The Flip: OpenSimAnt Is Public

*November 15, 2026*

**The repository is public.** `Jrbesse/OpenSimAnt` went from private to public earlier this evening, one day
after v1.0.1 shipped. This entry records what went out, what was verified before the flip, and what changes
for the pipeline now that someone who is not us can open an issue.

## What went out

- **The game.** v1.0.0 and v1.0.1 for Linux, macOS and Windows, cut from master and reproducible from source,
  with no original data in any package. The release page works anonymously — no GitHub account needed.
- **The code and the clean pack**, under the licences that have shipped inside every release package since
  #34: MIT for the code, CC BY 4.0 for the pack.
- **The full reverse-engineering reference** — the decompilation notes, the emulator architecture, the game
  tables, the module documentation and its ~8,800-line source. It reads a user's own copy of the 1991 game at
  runtime; nothing extracted from `SIMANT.EXE` is in it.
- **This dev log.**

What did *not* go out: a new binary. Nothing ships at the flip, because a published binary has no undo button
and v1.0.1 was cut while the repo was still private — the flip changed who can see, not what is there. The
README and every release body carry the line: an unofficial recreation, not affiliated with, endorsed by, or
sponsored by Electronic Arts.

## What was verified before the flip

A public repo is a one-way door for the code, so the audit went deeper than the usual pre-release pass:

- **Full history scan** — every ref, every commit, added-files only: zero original files. No `.NDX`, no `.DAT`,
  no `SIMANT.EXE`, no extraction output, ever committed. The originals are gitignored, and the game reads from
  the user's own copy at runtime.
- **Secrets scan of tracked files:** clean. The repo carries no secrets, so the CI that a public fork PR gets
  to run can leak nothing that is not there.
- **The similarity review** (#20, findings #51–#55): the clean pack against the original by palette index and
  shape measures. The numbers are in Dev Log #2; the five findings are open issues, not blockers.
- **Three owner calls, on the record** in `docs/PUBLICATION.md`: keep the name (an Open-prefixed original title
  has a 10–20-year precedent in OpenRA, OpenTTD, OpenXcom and OpenLoco, and the wordmark is a flat single
  colour); the RE reference stays public; no external legal opinion — if EA ever acts, that is the owner's
  direct call at the time.

## What changes for the pipeline

The overnight sessions, the reviewer and the merge job were built on a premise: every issue and PR came from
us. That premise is gone, so the fix was to make *trust* a machine-checked boundary instead of a prompt:

- **The reviewer never fetches, runs or reviews a fork PR.** The review gate executes the PR's head on a real
  box, so an external head is untrusted code, not a review target.
- **Sessions pick only issues carrying a priority label.** Labels can only be applied by accounts with write
  access, so an outsider's issue body can never become an agent's work order.
- **The fixer acts only on comments from our accounts.**

Everything from outside accounts — issues, fork PRs, comments — lands in the owner's morning report as the
external inbox. It is read; it is never executed.

## Next

Nine issues are open at the flip: the documentation corrections, the CI guard, and the four known pixel
differences (the edit-front stipple phase, two 2–9 px yard residues, and the file-dialog harness limit). When
that tail is short, the machine turns to the next project — **Formica**, whose M0 is done and whose twelve M1
issues come off the hold as soon as SimAnt's queue is nearly empty.
